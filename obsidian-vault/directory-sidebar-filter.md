Copilot sidebar is now portal-scoped: `CopilotSidebar` passes `portalContext={location.pathname}` to `AssistantView`. When `portalContext` is set, generic client heuristics (skills editor, leave forms, etc.) are bypassed — fixes the bug where "filter resources with 5+ yrs React" opened the Skills Editor in every portal sidebar. See [[focus-mode-routing]] for the parallel activeMode bypass.

Directory filter (built 2026-06-28): on `/directory`, `parseDirectoryFilter()` in AssistantView extracts 5 dimensions from NL — `{skill, minYears, certified, project, usedWithinMonths}` — and dispatches `window` CustomEvent `centriq:directory-filter` (same pattern as `centriq:requests-filter`). EmployeeDirectory listens, sets state, shows removable chips, and filters the grid against the **bundled Alchemy enrichment**: skill-level conds (skill name / `years_experience` / `certified` / `last_used` recency) must all hold on the SAME `skills[]` entry; project matches `projects[].name` or `skills_used`. Deterministic/zero-LLM by design — agent LLM tier is weak (llama3.1:8b, [[ml01-llm-environment]]).

**My Requests filter (added 2026-06-28):** same pattern on `/my-requests`. `parseRequestsFilter()` extracts `{type, status, dateFrom, dateTo, rangeLabel}` from NL ("find all my leave records from June") → dispatches the EXISTING `centriq:requests-filter` event (extended from status-only; MyRequests handler is back-compatible — status-only payload = legacy deep-link path). Type synonyms ordered specific-first (travel_expense→travel_request→expense). Date supports month names/this-month/last-month/year; un-yeared future month infers last year (records are historical). Added a clearable date chip; type/status reuse existing dropdown/tabs. Action intents (apply/submit/cancel) return null → fall through to backend.

**Sidebar UX (2026-06-28):** copilot is per-portal — each portal keeps its OWN chat thread (portalThreadsRef map in CopilotSidebar; fresh on first visit, restored on reopen, never bleeds across portals). Themed per portal via `src/lib/portal-copilot.ts` (`getPortalCopilot(pathname)` → {label, Icon, accent var, heading, tagline, starters[], placeholders[]}): drives copilot empty-state (icon/accent/heading/starter chips), Composer placeholder (new `placeholders` prop), and sidebar header label/accent. Composer `hideAttach` prop hides the image-upload (+) button in the sidebar. Header keeps the New-Conversation + button.

**Coverage:** filter matches rows whose enrichment is bundled in `/api/employees/directory` (`_attach_enrichment` → `get_cached_enrichment_map`). Cache is warmed by `alchemy_enrichment_sync_loop` (startup daemon, 6h cadence, gated on ALCHEMY_SKILL_SEARCH_ENABLED) covering ALL directory codes. Added 2026-06-28: `kick_enrichment_fill_async()` — `_attach_enrichment` kicks a deduped background full-sync whenever any row lacks cached enrichment, so coverage converges on actual usage, not just the timer (non-blocking, never raises). Un-synced rows still excluded until filled; empty-state hint says so. `portal_context` also sent to `/api/chat` as `{page, active_filters}` (backend injects page into system prompt; no server-side portal_action mechanism — frontend-driven only).
